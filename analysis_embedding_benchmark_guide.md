# Embedding Benchmark Analysis Guide

## 1. Purpose

The `analyze_embedding.py` script reads the raw CSV file generated by
the embedding benchmark and creates a report containing:

-   Every individual benchmark run for each embedding model (Run 1, Run
    2, Run 3, etc.).
-   An `AVG` row after each model's individual runs.
-   A CSV summary file.
-   An Excel summary file.

The script does not run the embedding models again. It analyzes the
measurements already saved in the raw CSV file.

## 2. Example project structure

``` text
ragLearn/
└── benchmark/
    └── embedding/
        ├── embedding_benchmark.py
        ├── analyze_embedding.py
        └── results/
            ├── embedding_results.csv
            ├── embedding_summary.csv
            └── embedding_summary.xlsx
```

-   `embedding_benchmark.py`: runs the embedding benchmark and creates
    raw results.
-   `embedding_results.csv`: stores every individual benchmark run.
-   `analyze_embedding.py`: reads the raw CSV and builds the report.
-   `embedding_summary.csv`: stores individual runs and average rows.
-   `embedding_summary.xlsx`: stores the same report in Excel format.

## 3. Requirements

You need:

-   Python 3.13 (or a compatible Python 3 version).
-   `pandas`: reads CSV data, groups rows, and calculates averages.
-   `openpyxl`: allows pandas to export an Excel `.xlsx` file.

Open PowerShell or your terminal and run:

## 4. Prepare the input CSV

Run the embedding benchmark first. It should create a CSV file with
columns similar to these:

  Column                   Meaning
  ------------------------ -------------------------------------------
  `timestamp`              Date and time of the benchmark run
  `model`                  Embedding model name
  `run`                    Run number
  `text_count`             Number of input texts
  `embedding_dimensions`   Number of values in each embedding vector
  `latency_seconds`        Measured latency in seconds
  `ollama_total_seconds`   Total time reported by Ollama, in seconds
  `load_time_seconds`      Model loading time, in seconds
  `texts_per_second`       Processing throughput

The analysis script expects the metric column names shown above. If your
CSV uses different headings, update the corresponding names in the
script.

## 5. Analysis script

Create a file named `analyze_embedding.py` in the `benchmark/embedding`
directory.

``` python
import pandas as pd

# Read benchmark results
df = pd.read_csv("results/embedding_results.csv")

# Sort by model and run number
df = df.sort_values(["model", "run"])

# Store detailed results and averages
result_rows = []

# Process each model separately
for model, group in df.groupby("model", sort=False):

    # Add every individual run
    for _, row in group.iterrows():
        result_rows.append({
            "model": model,
            "run": f"Run {row['run']}",
            "latency_seconds": row["latency_seconds"],
            "ollama_total_seconds": row["ollama_total_seconds"],
            "load_time_seconds": row["load_time_seconds"],
            "texts_per_second": row["texts_per_second"],
            "embedding_dimensions": row["embedding_dimensions"]
        })

    # Add the average row for this model
    result_rows.append({
        "model": model,
        "run": "AVG",
        "latency_seconds": group["latency_seconds"].mean(),
        "ollama_total_seconds": group["ollama_total_seconds"].mean(),
        "load_time_seconds": group["load_time_seconds"].mean(),
        "texts_per_second": group["texts_per_second"].mean(),
        "embedding_dimensions": group["embedding_dimensions"].iloc[0]
    })

# Create the final report
summary = pd.DataFrame(result_rows)

# Round numeric metrics for display and export
numeric_columns = [
    "latency_seconds",
    "ollama_total_seconds",
    "load_time_seconds",
    "texts_per_second"
]

summary[numeric_columns] = summary[numeric_columns].round(3)

# Display results in the terminal
print("\\n========== EMBEDDING BENCHMARK SUMMARY ==========\\n")
print(summary.to_string(index=False))

# Export CSV summary
summary.to_csv(
    "results/embedding_summary.csv",
    index=False
)

# Export Excel summary
summary.to_excel(
    "results/embedding_summary.xlsx",
    index=False
)

print("\\nSummary exported successfully!")
```

## 6. How the report is organized

The script processes one model at a time. It adds all individual run
records first, then calculates the average for that model and adds an
`AVG` row.

For example:

  Model        Run   Latency (s)   Speed (texts/s)
  -------- ------- ------------- -----------------
  bge-m3     Run 1         2.368             4.220
  bge-m3     Run 2         2.634             3.800
  bge-m3     Run 3         2.382             4.200
  bge-m3       AVG         2.461             4.073

The same structure is repeated for every model in the input CSV.

The average is calculated using the original values in the raw CSV,
before rounding the report values.

## 7. How to run the analysis

Open your terminal and move to the embedding benchmark directory:

``` powershell
cd D:\y3\ragLearn\benchmark\embedding
```

Run the analysis script:

``` powershell
py analyze_embedding.py
```

The script will:

1.  Read `results/embedding_results.csv`.
2.  Sort the records by model and run number.
3.  Display every run for each model.
4.  Calculate and append an `AVG` row after each model.
5.  Save the report as CSV and Excel files.

## 8. Understanding the metrics

  ------------------------------------------------------------------------
  Metric                   Meaning                 How to interpret it
  ------------------------ ----------------------- -----------------------
  `latency_seconds`        Measured latency for a  Lower is generally
                           run                     faster

  `ollama_total_seconds`   Total time reported by  Lower is generally
                           Ollama                  faster

  `load_time_seconds`      Model loading time      Lower means less
                                                   loading overhead

  `texts_per_second`       Number of texts         Higher is generally
                           processed per second    faster

  `embedding_dimensions`   Embedding vector size   A model characteristic,
                                                   not a speed score
  ------------------------------------------------------------------------

The `AVG` row contains the arithmetic mean of the time and throughput
metrics for that model. The embedding dimension is shown as the model's
dimension, not averaged as a performance metric.

Do not select an embedding model based on speed alone. Also evaluate
retrieval quality with suitable metrics such as Recall@K, Precision@K,
and Mean Reciprocal Rank (MRR).

## 9. Output files

After a successful run, the results directory should contain:

``` text
results/
├── embedding_results.csv
├── embedding_summary.csv
└── embedding_summary.xlsx
```

-   Keep `embedding_results.csv` as the original raw benchmark data.
-   Use `embedding_summary.csv` for data processing or sharing.
-   Open `embedding_summary.xlsx` in Microsoft Excel for easier reading
    and comparison.

The analysis script overwrites the summary files each time it runs. It
does not modify the raw benchmark CSV.

## 10. Troubleshooting

### `No module named pandas`

Run:

``` powershell
py -m pip install pandas openpyxl
```

### `No module named openpyxl`

Run:

``` powershell
py -m pip install openpyxl
```

### `FileNotFoundError`

Python cannot find the input CSV. Check: - The CSV filename. - The
folder where the CSV is stored. - The current working directory in the
terminal. - The path supplied to `pd.read_csv()`.

The example expects the script to be run from `benchmark/embedding`,
with the raw CSV inside its `results` subfolder.

### `KeyError` for a column name

The CSV may use a different column heading. Compare the CSV header with
the column names used in the script.

### Excel file is not created

Make sure `openpyxl` is installed and that the `results` directory
already exists. The script expects this directory to be present.
